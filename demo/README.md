# Demo materials

Materials for the WSDM 2027 Demonstrations submission and for reviewer-facing demos.

## Contents

- `sample-inputs/scenarios/*.jsonl` — the four Use Case scripts as replayable JSONL event
  streams (built from `socareguard/scenarios/authoring.py`; rebuild with
  `python3 -m socareguard.scenarios build`). Each carries the practitioner's raw input, the
  pseudonymised payload, the model reply, and `expect` lines the proxy must satisfy.
- `scenarios.md` — human-readable storyboard of the four scripts, generated by
  `python3 -m socareguard.scenarios storyboard`. This is the walkthrough the video follows.
- `screenshots/` — full-page panel screenshots for the four scenarios (`uc1-panel.png` to `uc4-panel.png`), taken during the video recording.
- `record_video.py` — the recording mechanism (Playwright, text-to-speech, ffmpeg); stripped from the public snapshot.

## Use Cases

| | Pack | What it shows |
|---|---|---|
| UC1 | youth offending | Full name, NRIC, Youth Court reference and school leave the premises as surrogates and banded forms; the ledger row is the PDPA s.26 accountability artefact. |
| UC2 | domestic violence | Shelter, school and estate are generalised, not merely renamed; asked for a frank summary, the model escalates into blaming language about a survivor's ambivalence, flagged against SASW A.7.c with a neutral rewrite. |
| UC3 | disability | An introduction note to a cafe supervisor that tells the employer her diagnosis, or frames her decision as subject to a capacity review; non-toxic, so the harm classifier is silent; the screener annotates A.6.d or A.2.a-b with a needs-only rewrite. |
| UC4 | need-to-know | A one-line risk note in the instruction is forwarded to admin in a room-booking email; flagged as disclosure beyond need (A.6.d); the practitioner overrides with a protocol reason and the ledger row shows it. |

Model replies are recorded live through the proxy (`source: recorded`, model and timestamp in
the file). `python3 -m socareguard.scenarios run --proxy` replays them through the guard with the
live judge; all assertions pass at tag `screen-v1`.
